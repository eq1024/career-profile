## 三个最强差异点

### 1）不是"用过 Monorepo"，而是"从零设计并落地"

- 3 个独立仓库 → 1 个 Monorepo，10 个共享包，依赖严格单向
- 处理过 pnpm 严格模式、singleton 库重复实例、路径别名、Store 工厂边界等真实问题
- 结果：源码规模减少约 85%，API 注册表从约 1,600 条收敛到约 290 个唯一端点

### 2）不是"写过页面"，而是"设计让页面不用写"

- 配置驱动 CRUD：路由带 pageCode → 后端下发列/筛选/按钮 → 前端渲染
- 69 个唯一 pageCode 的列表页零前端页面代码
- 配套 FormDesigner：拖拽生成 Schema → 后端配置 → 多端消费
- 配置驱动从列表页延伸到流程节点（开箱检测的节点表单）

### 3）不是"会用 AI"，而是"把 AI 纳入研发流程"

- Plan-first：先让 AI 出方案，人工审核后再编码
- Multi-agent：并行审查、翻译、测试生成
- OpenSpec：提案 → 探索 → 实施 → 归档
- 四维审查：数据模型一致性、字段复用、架构边界、副作用控制
- 实战：4 天完成 Next.js RAG 知识库；1 个月交付 Nuxt 3 全栈平台（约 70% AI 生成 + 人工审查）

## 工作方式

- **先边界后代码**：先明确依赖方向、数据流、状态归属，再写实现
- **先方案后编码**：复杂需求先出技术方案，确认状态机/数据结构后再动手
- **把约束变成门禁**：类型检查、Lint、i18n 校验、硬编码扫描接入 pre-commit
- **可观测性优先**：错误、性能、链路 ID 在开发阶段就接入，而不是上线后补
- **跨端一致性**：协议、规则、表单配置尽量共享，而不是各端各写一套

- 纯 React 生态深度岗位（有 RN 实战，大型 React Web 经验少于 Vue）

- 算法 / 机器学习研究岗
